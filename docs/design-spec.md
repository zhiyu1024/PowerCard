# 前端设计规范 · 远程电脑控制

参考图：`docs/reference-mockup.png`（765×403 概念稿）。目标：保留原稿的**安静、留白、单列居中**气质，同时把它做成手机可用的真实应用。

## 1. 风格基调

- 暖白纸感底色，大面积留白，细边框 + 极轻阴影；不堆叠玻璃拟态或重渐变。
- 绿色只用于“在线 / 开机”与主操作；红色只用于“关机”危险操作；其余中性灰。
- 中文系统字体，标题 semibold，数字使用等宽数字（`font-variant-numeric: tabular-nums`）。

## 2. 设计令牌

```css
--bg: #f6f4ef;            /* 页面底色，暖白 */
--surface: #fffefa;       /* 卡片 */
--surface-2: #f0ede5;     /* 次级面 */
--ink: #171b18;           /* 主文字 */
--muted: #6e746d;         /* 次级文字 */
--faint: #9aa098;         /* 辅助文字 */
--line: #e6e2d8;          /* 分隔线 */
--green: #129c52;         /* 主绿 */
--green-soft: #e7f5ec;
--green-deep: #0b6e3a;
--red: #cf4b3a;           /* 危险红 */
--red-soft: #fbebe7;
--amber: #c98a2b;         /* 演示/提醒 */
--amber-soft: #fbf3e2;
--shadow: 0 10px 30px rgba(28, 32, 27, .06);
--radius-lg: 22px;
--radius-md: 16px;
--radius-sm: 12px;
```

深色模式可选；若做，用 `prefers-color-scheme: dark` 覆盖令牌，保持对比度 ≥ 4.5:1。不做也可以。

## 3. 布局

- `.app`：`max-width: 560px`，水平居中，左右 padding 22px，底部留白 40px。
- 高度自适应：
  - 常规手机（≥ 700px 高）：头部 76px；hero 上下留白 24/30；主按钮高 108px；次按钮高 62px。
  - 矮屏 / 桌面概念稿（≤ 560px 高）：头部 56px；hero 更紧凑；主按钮高 78px；次按钮高 48px；整体尽量在 403px 高度内不出现首屏裁切。
- 单列；不要横向滚动。360px 宽可用。

## 4. 结构

### 4.1 顶栏

- 左：`远程电脑控制`（15px/600），下方副标题 11.5px muted：
  - demo：`界面演示 · 尚未连接设备`
  - live 内网：`局域网直连 · 每 10 秒刷新`
  - live 公网：`公网连接 · 每 10 秒刷新`
- 右：44×44 圆形图标按钮（滑杆/调试图标），`aria-label="调试与设置"`，hover 浅底。参考图右上角即此按钮。

### 4.2 状态区（hero，居中）

- 电脑显示器线性图标 52px（矮屏 40px），开机绿色 / 关机深灰 / 离线浅灰；在线时图标外有柔和绿色光晕。
- 主标题 30px/650：`电脑已开机` / `电脑已关机` / `状态未知` / 首次加载 `正在连接…`。
- 在线状态行：Wi-Fi 图标 + `开机卡在线`（绿点）/ `开机卡离线`（灰点）/ `正在检查…`。
- 元信息 11.5px faint：
  - demo：`模拟设备已连接 · 演示模式`（带 amber 小徽标也可）
  - live 成功：`最后更新 15:25:30 · 38 ms`
  - live 失败：简短错误，如 `连接超时 · 点击右上角检查设置`
- 演示模式增加一个 amber 小胶囊 `演示模式`，不要占据主视觉。
- 加载时标题用骨架 shimmer，不要整页 spinner。

### 4.3 控制区

- 主操作：两列等宽，高度更大；开机（绿）/ 关机（红）。图标 32px + 文字 17px/600，卡片白底、1px line、22px 圆角、轻阴影；hover 上浮 2px；按下缩放 .985。
- 次操作：两列等宽，高度较小；重启 / 刷新状态，水平排列图标 18px + 文字 14px，浅色幽灵卡片。
- 禁用：卡片离线或请求进行中，操作按钮 `disabled` 且 45% 不透明；刷新按钮始终可用（除非正在刷新，图标旋转）。
- 按钮有清晰 `:focus-visible` 环。
- 在线/关机等状态不改变按钮语义：两个主按钮始终存在，不把“开机”变成“已开机”。

### 4.4 确认弹窗

- 开机 / 关机 / 重启且 `confirmActions` 为 true 时出现。
- 居中卡片 340px，危险/成功图标，标题 `确认开机？` / `确认关机？` / `确认重启？`，说明 `指令将发送到开机卡，电脑会开始启动。` / `指令将发送到开机卡，电脑会立即关机。` / `电脑将立即重启。`
- 按钮：`取消`（幽灵）/ `确认开机`（绿）/ `确认关机`（红）/ `确认重启`（深色）。
- Esc 关闭；遮罩点击关闭；初始焦点在取消。

### 4.5 设置 / 调试抽屉

- 右上角调试按钮打开；桌面从右侧滑入 460px 抽屉，手机全宽全高；遮罩 `rgba(20,24,21,.34)` + 2px blur。
- 顶部：`调试与设置`（18px/650）+ 副标题 `接口地址与设备资料`，右侧关闭按钮。
- 内容分节，Section 标题 11px/600 muted + 0.08em 字距：
  1. **接口地址**：4 个 URL 输入框，label 分别为 `状态查询 URL`、`开机 URL`、`关机 URL`、`重启 URL`；每个输入右侧/上方有 `GET` 小徽标；等宽字体 12.5px；placeholder 示例 `http://192.168.1.50/status`。辅助文案：`服务端将以 GET 请求访问，可包含查询参数。`
  2. **设备网络信息**：公网地址、内网地址、子网掩码、默认网关、物理地址（MAC）。两列网格，MAC 占整行。地址旁有小型“打开”外链按钮（仅当地址非空）。
  3. **状态识别**：可选输入 `电源状态字段`（placeholder `自动识别，如 data.power`）、`在线状态字段`（placeholder `自动识别，如 data.online`）；辅助文案说明支持 JSON/纯文本、自动识别，识别失败可查看原始响应。
  4. **刷新与操作**：轮询间隔 select（5/10/15/30/60 秒）、请求超时 select（3/5/8/10 秒）、操作二次确认 switch。
  5. **连接测试**：`测试状态接口` 按钮 + 结果区（在线/电源/耗时/错误），调用 `/api/test`，不保存。
  6. **调试信息**：当前模式、`查看原始响应`（details，等宽滚动，含复制按钮）、`加载最近请求`（调用 `/api/logs`，列表显示时间/类型/URL/HTTP/耗时）。
- 底部 sticky 操作条：`保存并应用`（主绿，全宽），下方或旁边 `取消`。保存中禁用并显示“保存中…”。
- 表单校验：URL 为空允许；非空必须 http/https；轮询/超时用 select 不产生非法值；保存失败把字段错误显示在对应输入下方。
- 设置打开时若已有状态，调试信息直接展示当前 raw，无需额外请求。

### 4.6 Toast

- 底部居中，深色胶囊，白字 13px；成功/失败用图标或小色点区分；3 秒自动消失；最多同时 1 条（新替旧）。

## 5. 动效

- 统一 180ms `cubic-bezier(.2,.7,.3,1)`。
- 在线绿点 2.2s 呼吸；刷新图标旋转 800ms linear infinite；主按钮 hover 位移；抽屉 240ms。
- `prefers-reduced-motion: reduce` 时全部关闭动画（旋转改为静态）。

## 6. 可访问性

- 所有图标按钮有 `aria-label`；状态区 `aria-live="polite"`；toast `role="status"`。
- 抽屉 `role="dialog" aria-modal="true"`，打开时焦点移入，Tab 圈定，Esc 关闭，关闭后焦点回到调试按钮。
- 文字对比度 ≥ 4.5:1；点击目标 ≥ 44px。
- 状态不能只靠颜色表达，必须同时有文字。

## 7. 技术约束

- 原生 HTML/CSS/ES Modules，无构建步骤，无前端框架、无 CDN。
- 所有资源本地：`public/index.html`、`public/styles.css`、`public/app.js`、`public/manifest.webmanifest`、`public/icons/*`、`public/sw.js`。
- 遵守服务端 CSP：禁止内联 `<script>` / `<style>` / 内联事件处理器；样式全部在 `styles.css`，脚本在 `app.js`。
- 截图/视觉验证用 Edge；若无浏览器可用，至少用 DOM/静态检查与真实 API 联调。
